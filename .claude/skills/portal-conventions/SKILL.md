# Portal conventions

Docs: `../../docs/index.md` (layer docs). Layer rules: see the sibling skills `pages`, `api-routes`, `components`, `lib`, `request-gate`.

> Next.js here is 16.x with breaking changes from older versions. Check `node_modules/next/dist/docs/` before writing framework-level code. The request gate is `proxy.ts` (not `middleware.ts`).


- Import with the `@/` alias (`@/lib/session`, `@/components/NavBar`), not long relative paths.
- **Every screen must be responsive.** It has to fit and stay usable from a 320px Samsung/iPhone up to a wide desktop: fluid widths
  (no fixed widths wider than the screen), text that wraps, touch targets of at least 44px, and wide tables inside `.table-wrap`.
  Check it by adding the route to `e2e/mobile.spec.ts`, which fails on sideways overflow on iPhone and Samsung profiles.
- Match the surrounding code: naming, comment density, plain CSS classes from `app/globals.css`.
- Never write passwords, security answers or tokens to a log, the console, an error message or a response body.
- Tunables are env vars, documented in `.env.local.brite`. Text that quotes them (`lib/faq.ts`, `lib/legal.ts`)
  must read the same variable, so the wording cannot drift from behaviour.
- Identity belongs to the Spring backend (customer and employee logins, JWTs, privileges). The portal keeps the token in an
  httpOnly cookie and never decides permissions itself; do not re-add a local user store, 2FA, audit log or `.data/` state.
- Only go through the backend's BFF endpoints; never access its database directly.
- After a change, run `npx tsc --noEmit` and `npx eslint <changed files>`. Update the matching doc in `.claude/docs/` (and `README.md` if a
  screen, route or env var changed) in the same commit.
- Do not commit `.env.local` (gitignored). `AGENTS.md` / `CLAUDE.md` at the repo root are
  generated by `next dev`; leave them out unless asked.


## Before you commit

1. `npx tsc --noEmit` and `npx eslint` on the changed files pass.
2. The matching doc in `.claude/docs/` still matches the code; `README.md` updated for any screen, route or env var change.
3. Server-only code is not imported into client components; no secrets in logs or responses.
4. Only the files you meant to change are staged.
